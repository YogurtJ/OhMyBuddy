# 伙伴模式

> 尚未发布：本文描述当前源码行为，正式版本不含此功能。限制见[当前限制](#当前限制)。
>
> 界面中的“伙伴”（英文 Buddy）在开发中曾叫 Bot，“工作台”（英文 Workspace）原名 Pi Agent。接口路径、旧数据目录和微信 `/bot` 指令保留兼容，微信也可以用 `/伙伴` 或 `/buddy`。

伙伴是有名字、样子和性格的私人助理。每个伙伴有一个“主聊天”：像同一个人一直和你聊，不显示项目、线程、模型名或上下文压缩。工作台页面保持原样，继续面向需要完整工作台控制的使用方式；原“助手对话”页面已停用，由伙伴、话题和工作台的“以身份新建…”承接，旧数据都保留（见[助手会话分类](AGENT_PROFILES.md#助手会话分类助手对话页已停用)）。

每个伙伴本质上是一个[助手档案](AGENT_PROFILES.md)，有自己的“关于你”、长期记忆、技能、模型和工作目录。不同伙伴之间互不共享这些内容。后台学习也按每个伙伴单独配置和运行，主聊天和各个话题都会作为学习来源，聊天换到新的记录文件后也会继续接着学、不重复学习交接内容。

## 开始

服务端支持时，导航栏出现“伙伴”。还没有伙伴时显示欢迎页，点“开始”创建第一个伙伴并进入它的主聊天。新伙伴的初始名字跟随创建时的界面语言：中文为“新伙伴”，英文为“New buddy”；切换界面语言不会重命名已有伙伴。新伙伴默认使用内置“小石”头像，无需先选表情；已有伙伴保留原头像。

伙伴需要聊天模型才能说话。没有任何可用聊天模型时，欢迎页和问候里出现“接入模型”，打开“服务商与模型”设置；接入并刷新模型目录后，伙伴页面重新检查，出现“开始”。只要有可用模型，就不需要额外选择：伙伴跟随工作区的有效默认模型；没有保存全局默认时，使用 Pi 原生的自动选择。也可以在它的设置里单独指定，自动选择不会替你保存为固定模型。

## 互相认识

欢迎页、本地问候、认识收尾卡和设置的“更多”都提供可展开的“数据、权限与备份”说明，展示当前做事方式。新伙伴默认“放手”；允许的程序以服务机器的权限运行，工具确认不是系统沙箱。聊天、记忆和工作文件保存在运行 OhMyBuddy 的服务机器上，回复时会把相关上下文发送给已配置的外部模型服务；“以身份新建线程”仍使用普通 Pi 的工具和权限。

第一次打开主聊天时，伙伴在本地打招呼，这一步不调用模型。你可以开始两三分钟的访谈，也可以跳过，直接聊天。完整备份需在空闲停机时保存实际 Pi 身份目录、伙伴工作目录及关联媒体和配置，见[备份范围与一致性](INSTALL_RECOVERY.md#4-备份范围与一致性)。聊天里的 `/export` 只导出当前会话范围，不能作为整个伙伴的备份。

访谈按怎么称呼你、主要帮你做什么、伙伴的名字、性格、做事方式依次进行，每次只确认当前这一项。头像已经就绪，不再单独询问或要求选择表情；想换时可以在设置中修改，也可以之后在聊天里主动提出。之后再聊一两个还需要了解的关于你的轻问题，最后给出几件马上能做的事。还没想好主要让它做什么或它该怎么说话时直接说就行，它会先按通用方式聊，以后从你的要求里看出偏好再提出修改。

每张设置卡都可以稍后再决定：不保存卡片提出的值，其中尚未处理的访谈步骤记为跳过，伙伴接着聊下一项，以后随时可以在设置中补充。已经完成或跳过的步骤保持原状。确认卡片时也可以修改或不保存其中某项；未选中或清空的项若尚未处理，也记为跳过。保留与当前相同的名字、头像、职责或性格，也算回答了该项。做事方式在自己的卡片中确认一次；夹带在其他卡片里的未变方式不会被确认或跳过。保存名字不会同时完成头像步骤，默认头像也不算用户主动选过。

做事方式在访谈中单独选择一次：[放手、稳妥、每次都问](#做事方式)。设置卡可以保持当前方式，或改得更谨慎；之后只有实际提出改变做事方式时才再次出现选择。要给伙伴更多自由，需要在设置中修改。访谈还没结束时，在设置中改过的名字、头像、主要职责、性格和做事方式也计入各自的访谈进度。

设置卡保留标题和底部操作，内容较长时在卡片中间滚动。“主要帮你做”可以折行查看和编辑，保存时将换行整理为一句；性格保留段落。手机键盘挤占空间时，卡片和输入区随可见范围调整；空间很小时卡片可能暂时盖住头像牌，保存和以后再说仍可操作。保存失败后保留修改、阅读位置和正在编辑的位置。

名字和头像一旦定过，重新互相认识后仍保留这些选择。头像提供十二款预设：小石、豆豆、方方、滴滴、团团、软糖、小芽、薄荷、奶团、果冻、信号和小桃。也可以在“组合”中选择六种轮廓、八套配色、四种眼型、嘴部与装饰，锁住喜欢的部件后点“帮我搭一个”，或撤销、恢复已保存形象；旧三款的原版配色仍可保留。预设和组合先在本地预览，保存后才生效，刷新或以后新增部件不会重新随机。可以上传自己的图片（PNG、JPEG、WebP、GIF，最多 6 MiB；保存时转换为 PNG）。伙伴选择界面不再提供 emoji 输入；旧 emoji 或空头像在伙伴中回退显示“小石”，已保存的头像引用、历史和底层档案 API 的 emoji 兼容仍保留。这些选择只改变样子，不关联职责、性格或模型；已有伙伴保持原头像。点击预设先预览，保存后才生效；取消和保存冲突都沿用设置草稿规则。性格卡提供四种简短风格，也可以自由输入。访谈进度保存在伙伴设置中，刷新、换设备或隔几天再回来都能接着聊。设置卡的确认由服务端核对：这张卡须仍在该伙伴窗口当前一代的会话中等待回答，只接受卡上提出过的字段，并按档案修订保存；仅在其他客户端回答确认，不会写入设置。

记下的内容按用途保存：称呼、背景、目标、习惯和跨聊天的偏好放在“关于你”，本次聊天定下的事、答应的事和期限、等回答的问题、要记牢的名字和数字放在[我记着的事](#我记着的事)。同一件事也可以同时需要这两种记录。伙伴只有在保存工具成功后才会说已记下，并说明保存到了哪里。

### 第二个及以后的伙伴

新伙伴先列出其他伙伴已记下的“关于你”条目，默认全部勾选。取消不想让它知道的条目后选“记住这 N 条”，或选“不用，重新认识”。有多个伙伴时可以切换来源。只复制勾选且来源中仍存在的条目，已有条目不会重复；访谈随后不再问这些内容已经回答的问题。

复制是一次性的。之后每个伙伴的“关于你”各自保存，在一个伙伴中更新不会同步到其他伙伴。

### 在真实项目里用伙伴

伙伴的聊天和话题都在它自己的工作目录里。要让它在某个真实项目目录里工作，在工作台的项目菜单中选“以身份新建…”并选这个伙伴：新建的是该项目里的普通 Pi 线程，带着它的性格、记忆和技能，但工具和权限与工作台相同，不受伙伴的做事方式限制，也不出现在伙伴的聊天和话题里。

### 把已有身份变成伙伴

在“身份”页选中一个已启用的助手身份，在“更多操作”中选“变成伙伴”。确认后它保留名字、头像、性格、记忆和技能，新建自己的工作目录和主聊天，出现在伙伴页面。第一次打开时它以原来的名字打招呼，只问还没定下的事（主要帮你做什么、怎么做事；没写过性格的也会问性格），不会当作新来的重新起名，也不再从其他伙伴复制“关于你”。

以前用这个身份进行的对话不移动、不删除，仍在工作台的线程列表里（带身份标签），打开后照常使用它的性格和记忆，但不是伙伴的聊天或话题。以这个身份为目标的定时任务以后发到伙伴的主聊天，确认时会说明有几个。变成伙伴后不能再变回普通身份，可以像其他伙伴一样移到回收站。停用的身份要先启用。

### 认识之后的第一件事

新建或重新开始的访谈完成后，主聊天空闲时出现本地收尾卡：说明聊天、记忆和文件的保存位置，回复时使用所选模型，以及做事方式的作用范围。可以继续跟随默认模型，也可以选择一个可用模型和思考程度；保存失败或修订冲突时保留选择，成功后才显示已保存。没有额外的模型调用。

接着可选学习、安排计划、写东西、聊聊，也可自己说或以后再说。手机上保存位置与权限说明默认折叠，建议和离开选项放在可直接操作的位置；回复开始／结束或卡片刷新时保留你最后的展开选择。自己发了一条消息后，本页会先收起尚未选择的收尾卡；没有替你保存进度，刷新后仍可回来选择。只有你点击建议才会发送消息；输入框已有文字或附件时不会被覆盖，发送失败时文字留在输入框。这里完成的是引导中的选择，不代表伙伴已经执行完那件事。已经完成旧版访谈的伙伴不会自动重新进入这些步骤。

## 主聊天

伙伴的大头像悬浮在聊天顶部，下面是圆角名字牌，点头像或名字牌打开设置。名字牌第一行是伙伴名字和状态，在话题里第二行显示话题名，两者不再互相挤占；空闲和正常工作只显示状态圆点（工作时跳动，悬停或读屏仍有文字），等你确认、回复未完成、正在停止和断线等状态保留文字。头像两侧的聊天内容可以滚动到顶部，并逐渐淡出、模糊，顶部不再单独占据一整行；刚开始的消息与“更早的聊天”控件留有初始间距，这段间距会随聊天滚走。每条回复不再重复小头像。你的消息在右侧主题色浅底气泡里，伙伴回复在左侧柔和底色气泡里，表格和代码可以展开到阅读宽度；相隔十分钟以上的用户消息显示居中时间。输入框提示“给 {名字} 发消息”。工作台的项目、模型、上下文和运行控制在伙伴页面中隐藏；需要这些控制时使用工作台页面。右上角 `⋯` 提供侧聊、我记着的事、定时任务、助手身份详情和伙伴设置；定时任务默认按当前伙伴筛选。点击头像或名字牌也可打开伙伴设置。侧聊支持 `/btw` 和选文提问，独立讨论时主任务继续；电脑并排显示，手机使用全宽面板。收起后的新回复、运行和待确认状态会在 `⋯` 上提示。任务进度在主聊天区已有的进度卡查看，侧聊不再重复展示。更多菜单按选项内容高度展开；侧聊设置中模型与思考等级同排，背景范围与更新并新开按钮同排。侧聊背景仍是首次发送时的快照，后续不会自动更新，详见[侧聊](SIDE_CHAT.md)。伙伴聊天不提供“从此回复后分叉”，`/fork` 和 `/clone` 继续提示不可用。

每轮回复只留一个正文气泡；中间的过渡说明、思考和工具步骤收在用户消息与回复之间的一行过程里。运行中显示最近的过渡说明或当前步骤和用时，需要确认时显示“等你确认”，连接重试时说明正在重试；刚发送、还没有步骤时保留“正在发送／正在思考”。结束后默认折叠成“用时 · N 个步骤”，点开可回看轻量时间线，再点步骤看参数和输出、点“想了想”看思考原文。中途没成功但继续完成的步骤用灰色标记；最终回复失败或停止仍明确提示。伙伴不提供详细程度开关，完整工作台记录可到工作台页面查看。

这一轮保存的记忆、技能、设置和[我记着的事](#我记着的事)会在回复下方显示回执；记事本同轮多次保存合并，过程摘要也会写“记下 N 件事”。点“查看”打开对应记事本、身份分区或伙伴设置。知识回执继续保留撤销、标为不对和编辑；旧回执缺少保存位置时仍显示“记下了”。定时任务保留查看／修改和取消按钮。工作台的记忆回执栏和“本轮文件”编辑记录不在伙伴页面显示。伙伴交给你的文件显示为文件卡，点文件名在右侧（手机为全屏面板）预览，右侧下载按钮下载原文件。

伙伴的回复和普通工作台一样可以读写文件、执行命令、上网和使用已配置的工具。它创建的文件默认放在自己的工作目录：新建伙伴默认使用 `~/OhMyBuddy Workspaces/bots/bot-<完整 ID>/`，可用 `OHMYBUDDY_WORKSPACES_DIR` 指定独立工作根。目录中的 README 说明归属；改名不移动目录。不会回退到项目根、源码或安装目录；旧伙伴继续使用档案中保存的目录。更新、卸载和迁移边界见[存储布局](STORAGE_LAYOUT.md)。

### 形象状态

所有内置预设与组合形象共用八种姿态：待机、思考、工作中、等你、完成、出错、打盹、问候。不同轮廓有自己的脸位，眼型可切换闭眼、笑眼与受挫表情；小芽、天线和腮红只出现在兼容位置。顶部使用已有会话和工作状态：待确认事项优先保持“等你”；模型首包等待或思考阶段显示思考，工具、回复正文或后台子任务显示工作姿态；仅有排队任务时保持中性姿态，文字说明排队。本轮正常结束时短暂反馈，最终失败保留错误姿态；中途一个工具失败不等于整轮失败。前台确认空闲、无工作或待办后，五分钟没有点击或按键可打盹，交互或新工作立即唤醒。断线或重连暂停动态，连接情况继续用文字表达。

“等你回复／确认”使用头像外的琥珀色入口，静态图片也能显示；多项时显示数量，点击定位当前聊天里的问题或确认卡，不会替你回答。头像与名字仍打开设置，其他聊天的状态继续由聊天列表表达。列表、身份页和历史里的形象保持静态。设置中可切换八状态预览，点“播放动作”才播放当前预览；“播放形象动画”立即保存为当前浏览器的偏好，系统的“减少动态”仍优先关闭动作，姿态与文字保留。切到后台暂停，回来按当前状态恢复，不补播旧完成或问候。

只有网页实际观察到的一轮正常回复结束、且没有待确认事项或其他工作时，才短暂显示完成姿态。停止、取消、断线、单次可恢复工具错误不会触发庆祝；明确终止的助手回复错误才使用出错姿态。新伙伴的本地问候可短暂摆动一次；新工作、导航、待确认事项和页面隐藏会打断旧效果，结束后重新计算当前状态。首版不单独推断推理阶段或闲置时长，思考／打盹保留姿态但运行中回退到工作中／待机，不新增模型调用或状态轮询。未知的已保存预设安全回退显示，保留原引用以便资源恢复。

### 长期聊天的维护

主聊天可以一直用下去，工作台在后台按下面的顺序维护它，不需要操作，也不在页面上提示：

1. **省略旧的工具输出**：上下文用到窗口的 35% 以上、且一次能省下至少 1 万 token 和当前上下文的 20% 时，在回复结束后把最近 3 次发言之前、4000 字以上的工具输出换成一行说明（伙伴需要时可以重新查看）。“我记着的事”的记录和设置卡不会被省略。
2. **空闲时整理摘要**：回复结束后隔了一段时间（至少 10 分钟，模型提示缓存更久时等到缓存过期）仍没有新消息，上下文用到 55% 以上、且 Pi 原样保留的最近部分之前还有足够多（至少 2 万 token 和窗口的 20%）可以整理时，在后台整理一次摘要，下一条消息不用等它。窗口快满时 Pi 自己的自动压缩仍然生效，摘要方式相同。
3. **结构化摘要**：摘要用这个伙伴的模型和思考程度，写成“在聊什么 / 经过 / 现在进行到哪”，并同步[我记着的事](#我记着的事)。你和伙伴说的话完整交给摘要（很长的一条分段读），工具输出只取开头。回答缺少任何一部分、无法解析或请求失败时改用 Pi 原生的摘要，下一次回复前伙伴会重新看到完整的“我记着的事”。
4. **换代**：当前会话文件达到 8 MiB、8000 条记录或 60 天时，接续到新的原生会话文件。换代总是紧接在一次摘要之后（通常在空闲整理时一并进行），这次摘要还会核对 Pi 原样保留的最近部分，使“我记着的事”在换代前同步；如果这次改用了 Pi 原生摘要，或摘要之后又有新的回复，就等下一次摘要。内容太少、没有可整理部分的会话暂不换代。新会话开头带有不显示的交接内容：“我记着的事”、最近的摘要、摘要之后的文字原话（最多 64000 字符、400 条消息，不含工具输出和图片字节）、模型和思考程度。通过维护接口手动换代时，这些原话可能还没整理过，新会话的第一次摘要会把它们当作原话读入并核对。

伙伴回答涉及更早内容时，可以在这个聊天的各代里翻找原话（“翻找之前的聊天”），并查看某条消息前后的原文；它只读这些会话文件，结果会说明覆盖和跳过了哪些代。查看原文每条最多 6000 字符、合计最多 16000 字符，超出会明确省略。

微信发来的文字与图片附带文字也按你的发言处理，参与回忆、摘要、记事本出处、换代交接和后台学习；投递说明不算你的原话。系统、定时任务、子任务和无法核实来源的扩展消息不会因此变成用户发言。所有读取沿用原生分支和最后的上下文编辑，不改写原记录或另存聊天副本；交接保留原会话、条目、时间与渠道来源，重复换代不会把旧引文变成新发言，或把已删除的记事本内容重新记回。

### 更早的聊天

换代之前的内容显示在当前聊天上方，标为“更早的聊天 · 日期范围”，点开后逐段只读回看，“再往前看”继续展开更早一段；没有任何对话的一代自动跳过。这些内容从服务器读取原生会话文件，不启动旧会话的运行实例。

页面断线重连或换代时，伙伴页面总是重新确认主聊天当前所在的会话再连接，不会回到已经换下的旧会话。

当前会话发生过上下文压缩时，伙伴页面不显示压缩提示，压缩前的内容同样标为“更早的聊天”。

换代保留每一代完整的原生会话文件。换代过程中断时，下次打开主聊天前工作台先按原生证据恢复：只有新会话完整写入、并能证明接在旧会话最后一条记录之后时才采用，否则继续使用原会话，不会重放已经发生的对话。

### 在其他页面中

伙伴的原生会话仍会出现在工作台页面的 自身工作目录对应的项目下，可以按普通线程查看。它们不能移动到其他项目，也不能按线程绑定微信；微信要按伙伴连接（见[在微信里聊](#在微信里聊)）。打开旧的指向伙伴身份的助手对话链接时转到该伙伴的主聊天。

### 各个伙伴在做什么

左侧伙伴栏在其他伙伴的头像上标出动静：琥珀色圆点表示有事等你确认，数字表示它有几个聊天出现了你还没看的新回复。聊天列表中，当前伙伴的其他聊天也会标出“等你确认”（电脑上为琥珀色圆点，悬停可看文字）、新回复（主题色圆点）或正在忙（绿色圆点）；你正在看的聊天不另加标记，状态显示在顶部名字牌。这些标记来自页面原有的工作状态刷新，不额外启动运行实例或调用模型。

手机上有两个以上伙伴时，菜单抽屉顶部有“所有伙伴”，其他伙伴有新回复或等你确认时显示“另有 N 个有动静”。点开后是伙伴首页：按设置中的顺序列出每个伙伴（顺序不会因新消息变化），显示等你确认、正在忙（以及在哪个聊天）或它主要帮你做的事，有新回复的聊天数，以及一个最值得看的话题入口；“话题 N”打开这个伙伴的聊天和话题列表。可以按名字或话题名搜索，并筛选“等你确认”“有新回复”。工作状态暂时读不到时显示“暂时看不到它在做什么”，不会当作空闲。首页不显示消息预览或时间。点任一伙伴进入它的主聊天，点返回或按 Esc 回到刚才的聊天；首页打开期间新回复不会被自动标为已读。上次打开的伙伴和伙伴地址的行为不变。

## 话题

同一个伙伴可以有主聊天和多个话题。电脑在左侧聊天列表、手机在菜单抽屉中点“新话题”，直接打开一个全新的话题窗口并聚焦到输入框，随时开始提问，初始名字跟随界面语言（“新话题”或“New topic”）；首轮问答完成后自动生成话题名与“专注什么”，后台整理摘要时也会为空白的关注点自动补充，之后随时可点话题旁的编辑按钮修改。编辑页第一行是图标和话题名：没有图标时显示空的虚线图标位，点开可从常用表情选择、粘贴自己的表情或不使用图标；自动命名不会覆盖图标。分组是一行下拉，“专注什么”显示字数，说明只在填写时出现；归档和移到回收站放在单独的底部区域，都要点两次确认。每个话题从一段全新的对话开始，不复制主聊天内容；共享这个伙伴的性格、模型和长期记忆，“我记着的事”和聊天历史各自独立。最多 100 个正常话题，包含已经归档的；回收站中的话题另算。

话题列表的搜索与分组筛选放在同一行，右上角“整理”打开整理话题，顶部用分段切换“移动话题／管理分组／回收站”，回收站显示数量。移动页用一排分组标签切换全部、未分组或指定分组（手机上可横向滑动），话题以带图标的列表显示；勾选后底部才出现目标分组和“移动”，未选择时只显示一句提示。默认查看未分组；全部视图按当前分组分段；搜索保留已选话题，切换来源分组会清除选择，避免移动隐藏的选择。目标分组与所选话题相同时不提交无效移动。“管理分组”直接列出每个分组及其改名、上移／下移、删除图标按钮，改名在分组行内完成，删除前说明话题会回到未分组。回收站每行显示原分组和聊天段数，“恢复”为主要操作，“彻底删除”需输入话题名确认。

话题列表的“整理话题”提供分组和批量移动。每个伙伴独立管理最多 50 个一级分组，名称最多 60 字；一个话题最多属于一个分组，也可以不分组。没有分组时保持平铺；有分组时可以展开、收起、按分组筛选，并按名字或关注点搜索。可以调整分组顺序，也可以一次选择多个话题移动或新建分组。删除分组只会将其中话题移到“未分组”（包括已归档和回收站里的话题），聊天记录保留。分组只整理列表，不添加提示词，不改变身份、模型、记忆、权限或工作目录，不沿用已退役的助手分类。

编辑话题时可以展开“话题指令”（可选，默认收起，收起时显示第一行预览）：在这个话题里它要一直遵守的做法，比如回答格式、资料来源。可以写多行，最多 8 KB（约 2700 个汉字）。修改从下一条消息开始生效，不用重新打开聊天；指令仍受做事方式和安全规则约束。主聊天没有话题指令；伙伴提议的话题也不带指令，只能由你自己填写。

伙伴也可以建议另开话题，确认卡会列出名字和关注点；任何做事方式都需要你确认，成功后才出现“打开话题”回执。创建不会自动打断当前聊天或切换页面。

不用的话题可以归档，历史保留；从“已归档的话题”恢复后继续使用原来的聊天。归档中的话题不接受新消息或定时运行。正在回复、等待确认、还有排队或后台工作、预约消息、侧聊、换代或关联定时任务时，先处理这些工作再归档，不会自动清掉它们。主聊天不能改名或归档。在另一台设备归档当前话题后，本页会提示并回到主聊天；当前伙伴被移到回收站时，会刷新列表并转到其他可用伙伴或欢迎页。修改发生冲突时保留草稿，核对刷新后的内容再保存，不自动重试。

这里的回收站是 **OhMyBuddy 应用内的可恢复回收站**，与工作台优先使用操作系统回收站的会话删除不同：保留文件以便恢复，不会因此释放磁盘。网页普通伙伴列表只请求正常／归档话题和回收站数量；仅在打开回收站时请求轻量摘要，列表不会打开原生聊天正文或启动 worker。真正移除原生聊天文件的是下面的“彻底删除”。

删除话题会先将**整个话题**移到回收站，包括所有“更早的聊天”和话题记事本。列表底部的“回收站”可以恢复，原来的分组和归档状态保留；原分组已删除时恢复为未分组。回收站不自动清空，最多保留 100 个话题，不占正常话题额度；正常话题已满时需先腾出名额才能恢复。主聊天不进入这一删除流程。

回收站中的话题不接受网页、工作台原生入口、微信、定时或延迟消息，也不再作为后台学习来源。移入回收站或彻底删除前，须等当前工作、换代、排队消息、侧聊、后台学习和媒体任务结束；关联定时任务要先调整或取消，不会悄悄转发到主聊天。未开始的伙伴主动跟进会取消，恢复不会自动重放它们。已经学入伙伴记忆、技能的内容，以及单独保存的文件、媒体和成果，仍在各自入口管理。

伙伴或话题移入回收站、话题归档时，图片与原生记录一同保留，恢复后仍可看图。话题彻底删除前会登记所有历史代际的外置图片，删除中断时保留保护；成功后进入待核对范围。共享图片不会随一个话题立即删除，可到设置 → 用量统计 → 附件用量与清理检查“会话图片与 Buddy 图片”，先隔离无引用图片，30天后再确认永久清理。

“彻底删除”仅在回收站内提供，需要输入话题名称并单独确认。它删除全部原生聊天文件和其中的记事本，不能从应用恢复；外部文件、独立成果和已有备份不受影响。如果磁盘操作中断，话题会显示“删除尚未完成”，不能恢复成一段缺失历史的聊天；检查后再次明确确认可继续删除，不会自行重试或报告成功。

主聊天可以看到其他活跃话题的未了事项标题索引，取自各自记事本中的待回答问题和未完成承诺。索引有数量和读取预算，忙碌、暂时不可读或超出预算表示未知，不等于没有事项；不会为此启动话题运行实例或额外调用模型。

## 我记着的事

“我记着的事”是这个聊天的记事本，记下你定下的事、答应的事（谁答应、截止哪天）、还在等答案的问题、这段聊天的偏好和要求，以及要记牢的名字、编号、数字和日期。它只属于当前聊天；跨聊天的“关于你”见设置里的“记忆和关于你”。

- 伙伴在聊天中随时记下和更新，记下的那一刻就写入会话文件（伙伴从脚本里一次记几件事也一样），回执说“记下了”的事都能在列表里看到；伙伴自己没看到记录结果的（例如在脚本里记的），下一次回复前会再告诉它。整理摘要时还会对照原话补记和同步，例如你说过“不用了”的事会标为不需要。补记必须引用原话：“已经定下的”和“偏好和要求”只认你说过的话，伙伴的建议在你接受之前不算定了。
- 电脑在伙伴列表底部（“{名字} 的设置”上方）打开，手机点顶部右侧的图钉，或在左上角菜单中打开。
- 按“答应的事、等回答的问题、已经定下的、偏好和要求、要记牢的信息”分组。答应的事和等回答的问题左侧有圆圈，点一下标为完成（已有答案）。每条可以修改内容和截止时间（日期，可再填几点几分；只说了日期的保持为日期）、标为“不需要了”或删除；删除前会再确认一次，删掉后伙伴不再记得，之后整理摘要也不会根据删除前的原话把它记回来（你重新提起时可以再记；只记最近删除的 1000 条）。已完成、不需要了和被新内容取代的事收在底部，可以重新打开。
- 列表底部说明“关于你”的保存位置，并可直接打开它；列表为空不代表伙伴没保存个人事实。
- 点“出处”显示这条来自哪句话（你说的、伙伴说的或查到的内容），换代后仍然保留。
- 截止时间显示为月日；有具体时刻的显示到几点几分（按这台设备的时区），不是今年的另显示年份。
- 修改在聊天空闲时保存。没保存成功时（伙伴正在回复、网络断开，或其他设备和伙伴刚刚改过、列表已自动刷新），编辑框里你写的内容保留，可以稍后再点保存；刷新后你没动过的内容和截止时间跟着更新，保存时只提交你改过的部分。这台设备时区里不存在的时刻（夏令时开始时跳过的那一小时）不能保存，会提示换一个时间。你的修改会在下一次回复前告诉伙伴。

## 设置

点击聊天顶部的大头像，或伙伴列表底部的“{名字} 的设置”（手机也可用左上角菜单）。设置分为七个分区：电脑和平板上左侧列出分区，每项下面显示当前值（例如“放手”“开 · 23:00–08:00 安静”），右侧显示所选分区，打开时先显示“资料”；手机上先显示概览，点一项进入该分区，左上角返回概览。

| 分区 | 说明 |
|---|---|
| 资料 | 名字（最多 40 字）；十二款预设、组合形象或上传图片（可恢复已保存形象、移除图片），选择先预览，保存后生效；主要帮你做什么（伙伴以此为主要职责）；性格（说话方式与个性，即 SOUL，下一条回复起生效）。长文字下方显示已用字数 |
| 模型 | 模型与思考程度独立保存，各自可跟随默认；作用于整个伙伴主聊天和所有话题的后续回复，不影响其他伙伴或工作台。微信 `/model`、`/thinking` 与这里共用设置 |
| 做事方式 | 放手（默认）、稳妥、每次都问三张卡片，各有一句话说明和自由度刻度；选中的方式下列出“直接做”和“先问你”的事，“稳妥”和“每次都问”另列直接拒绝的事。“安全边界”和“一直允许的事”默认折叠，后者可查看、撤销。见[做事方式](#做事方式) |
| 主动联系 | 主动联系开关、安静时段、每天推送上限、准备跟进的事、有界的最近活动与结果，以及模型调用和额度说明，见[主动找你](#主动找你) |
| 微信 | 已连接的微信聊天，连接允许的微信用户或断开；还没有可连接的用户时提示先打开消息渠道设置。见[在微信里聊](#在微信里聊) |
| 学习与记忆 | “让它从聊天里学习”开关，说明学习内容（默认把你的纠正和偏好记到记忆里；复盘和技能草稿在“更多学习设置”里打开，技能草稿看过才会启用）和每天最多调用模型的次数（如“每天最多 20 次”）。缺少辅助模型时可直接打开辅助模型设置，今日次数或额度用完、最近连续失败时显示提示；“更多学习设置”打开该伙伴身份页的“学习”页，“记忆和关于你”打开“关于你” |
| 更多 | 当前做事方式与数据、权限、备份说明；“重新互相认识”确认后回到主聊天重新访谈；“移到回收站”停用并可恢复伙伴 |

微信的连接与断开、取消准备跟进的事和学习开关标有“立即生效”：操作后马上保存，不需要点“保存”，也不算设置里的修改。其余改动点“保存”才生效：改过的分区在列表或概览上显示小圆点，底部写明“未保存：…”；名字为空或安静时段开始和结束相同时，底部显示原因，点“保存”会跳到对应分区。手机上没有修改也没有提示时不显示底部按钮。

图片在保存时先上传；若上传成功而其余设置保存失败，图片已成为头像，取消离开时会提醒，可在设置里再改。预设不会在取消时写入。只保存改动过的字段。设置在别处刚被修改时，窗口重新读取最新设置并保留你的修改，提示检查后再保存一次。有没保存的修改时（包括暂时无效的修改，例如名字被清空），关闭、按 Esc，或点“记忆和关于你”“更多学习设置”等去往其他页面的入口，都会先提醒一次，再做一次同样的操作才放弃修改；切到其他页面或伙伴、直接改地址和浏览器前进／后退也沿用这个保护，不会在加载页面时悄悄丢掉草稿。保存或头像解码中不能离开；“重新互相认识”和“移到回收站”的确认框会一并说明将放弃这些修改。

### 模型与思考程度

选择“跟随默认”时，设置和认识收尾卡显示服务器解析的有效默认模型，并提供它支持的思考程度；无法核实时不猜测目录第一项。只改思考程度不会固定模型。思考程度依次使用显式伙伴偏好、所选模型的原生偏好、工作区全局默认，均未保存时才用 Pi 原生回退；自动选择模型不会丢掉已保存的全局思考默认。恢复默认模型保留独立思考偏好；恢复默认思考程度才会清除该偏好。

新选择按实际可用模型和支持的等级验证，不支持的组合会明确拒绝，不会悄悄更改另一个设置。已经保存但暂时不可用的模型或等级仍可保留、查看或清除。全局默认改变后，如果不再支持独立思考偏好，该偏好仍保存，本次采用模型原生支持的等级并给出警告；可以改选支持的等级或恢复默认。

模型在打开窗口和下一轮回复前对齐；进行中的回复以及已准入、尚未结算或待核对的定时任务保留原来的模型和思考等级。微信首张图片也先应用伙伴已保存的模型，再核对视觉能力。所选模型暂时不可用时保留设置、提示并继续使用当前模型。

### 移到回收站

在伙伴设置中点“移到回收站”，确认后停用这个伙伴，从列表隐藏；聊天、工作目录、记忆和文件都保留，可以到“身份”页的回收站恢复。设置有未保存修改时，确认框会一并提醒，确认后放弃这些修改。伙伴仍在工作、排队或有后台任务、未处理的预约消息、关联的定时任务及已受理但未完成的定时运行时，操作会被拒绝，不会自动取消这些内容。成功前会核对修订和原生窗口身份，并停止该伙伴的空闲运行实例；失败时保留设置窗口，不假称已移走。

### 做事方式

| 方式 | 伙伴直接做的事 | 先问你的事 |
|---|---|---|
| 放手（默认） | 与工作台 Agent 一样完全放手：工具层不做额外拦截，直接读写任意文件、运行任何命令与脚本、安装依赖与管理服务、上网、记忆、定时任务、交给其他助手等 | 仅建议另开话题（`bot_topic_propose`）与引导设置卡会弹出确认；对外发消息、明显花钱和修改自己的权限仍按指令先确认 |
| 稳妥 | 大多数事直接办：阅读、上网、记忆、提醒、图片与语音；读写普通文件（含 Shell 配置等）及 OhMyBuddy/Pi 状态路径（`.pi/agent`、`ohmybuddy-profiles`、`ohmybuddy-bots`、`.pivane`）；运行普通命令、脚本、安装依赖、交给其他助手等 | 短名单：`sudo` 等提权、递归或磁盘级删除（`rm -r`、`find -delete`、`mkfs`、`dd of=`）、关机、结束进程和服务控制、`git push`／`reset --hard`／`clean -f`／`branch -D`、发布包或版本、发邮件、定时或开机自启任务、可识别的凭据文件与私钥，以及读写 OhMyBuddy 自身的 `.ohmybuddy-runtime` 目录；写目录、自启动位置和工具标记为破坏性的操作；对外发消息、明显花钱和修改自己的权限 |
| 每次都问 | 阅读普通文件、查询和回答 | 其余每一步（弹出确认），包括读写 OhMyBuddy/Pi 状态路径、在工作目录内写文件、运行任何命令、记下关于你的事、把文件交给你和取出上传附件的原件（凭据与私钥直接拒绝） |

设置中按方式列出的“直接做”“先问你”和直接拒绝的事是本表与下文的简要概括。

三种方式都在工具层检查：需要确认时，输入框上方出现卡片，写明要运行的命令、文件路径或其他操作；点“允许”只允许这一次，“不要”、取消或 30 分钟内没有回答则不执行。伙伴不会重放或绕过未获允许的步骤。多步等待时逐个确认；某一步已被取消时，卡片随之消失。同一会话在工作台页面打开时使用通用确认对话框。定时任务运行中没有人确认，需要确认的步骤直接不执行。读取设置失败时使用“每次都问”，不沿用不确定的长期规则。

对于规则能理解的非危险命令或单个文件写入，确认卡还可选择“以后都允许”。第一次点击会展示确切操作和作用范围，再次确认才保存，并只在原请求仍有效时允许当前这一步。规则只匹配同一工具、同一工作目录与完全相同的命令，或同一工具与确切文件路径；不是通配符、整目录或任意命令授权。危险、无法判断或敏感操作不提供这个选项，长期规则也不能绕过它们。在设置中可查看和撤销已识别规则，撤销与其他修改一起保存；当前版本不识别的旧规则保留但不作为授权使用。修订冲突时不自动新增规则或回答确认。

伙伴的目录内容搜索会逐个核验文件，再在已核验的内容上匹配；敏感文件不会因为搜索了父目录而带入结果。搜索有文件数量、大小和时间上限，文件改变、编码不支持或预算用尽时会说明结果不完整，不能据此断言其他文件没有相关内容。PowerShell 文件选择器中的通配符不能获得一次或长期放行；明确的字面路径仍按路径规则检查。

“放手”与工作台 Agent 一样，不在工具层拦截命令或文件访问。“稳妥”和“每次都问”中，路径检查与 Pi 工具的路径解析保持一致，并核对可识别的真实路径、符号链接和硬链接；无法可靠判断的文件身份拒绝访问。macOS 的 `/etc`／`/var` 与其真实路径 `/private/etc`／`/private/var` 使用相同的系统与自启动规则；系统文件不提供长期允许，自启动位置仍需按做事方式确认。OhMyBuddy/Pi 状态路径（`.pi/agent`、`ohmybuddy-profiles`、`ohmybuddy-bots`、`.pivane` 等）在“放手”和“稳妥”下可直接读写，在“每次都问”下需逐次确认；可识别的凭据文件与私钥（`auth.json`、`.env`、`.ssh`、`*.pem`／`*.key`、`ohmybuddy-channels` 等）在“放手”下不做工具层拦截，在“稳妥”下需逐次确认，在“每次都问”下直接拒绝，且状态与凭据路径都不提供“以后都允许”长期规则。它仍是工具层的规则检查，**不是操作系统沙箱**：允许的命令以 OhMyBuddy 服务权限运行，不会隔离其程序内容、环境或后续行为；“每次都问”中复杂程序和无法理解的命令需要单次确认；“稳妥”只识别上表短名单，藏在复杂脚本里的危险操作不一定能认出来。“稳妥”和“每次都问”下查看整个环境变量（`env`、`printenv`、不带参数的 `export`／`set`）会拒绝，设置变量后运行命令不受影响。对外发送、明显花钱等不能从工具参数可靠识别的意图，还依赖伙伴的指令和对应功能自身的确认流程。

## 定时任务

可以直接在聊天里请伙伴创建单次提醒或重复任务、查看任务、取消任务。一次还是重复、哪一天不明确时，伙伴会先问清楚；只有工具成功后才说已设好，并报出本地时间和时区。按“做事方式”，“放手”和“稳妥”直接执行，“每次都问”在创建、取消前显示确认卡，查看任务无需确认。任务也可以在[定时任务](SCHEDULED_TASKS.md)页面查看和编辑。聊天里创建的任务发到提出请求的窗口（主聊天或话题），换代后自动跟随该窗口；用户要求的任务按指定时间执行，不受安静时段影响。定时任务运行中不能再创建任务。

成功的聊天工具结果显示定时任务卡，列出标题、时间、时区和要做的事；“查看 / 修改”直接打开该任务，取消时核对调度器的当前修订，冲突时不自动重试。卡片是创建／取消时的回执，任务当前状态以定时任务页面为准。

## 主动找你

伙伴可以自己发起两类消息：你和它说好的事（记在“我记着的事”里、带截止时间的承诺）到期时，它会来提醒你或问问进展；聊天中觉得过几天回来看看确实有帮助、而你没有要求提醒时，它可以给自己约一次“回来看看”（只此一次、最多 60 天后，每个伙伴同时最多 10 个）。这些消息只发文字，不使用工具、不会自己动手做事，发到原来的主聊天或话题里，聊天中显示为“主动跟进”卡片，只露出简短标题。只写日期的承诺在当天上午 9 点跟进；改了截止时间会改到新时间，标为完成或取消后不再跟进，同一条已发过的不会重复。到期时如果服务停了超过两小时、话题已归档或伙伴已移到回收站，这次跟进不再补发；聊天正忙时稍后再发。

在伙伴设置的“主动联系”中可以：

- 关掉“让它主动找我”：不再新增或发送这类消息（已排队还没开始的也不发），也不再推送；伙伴也不再给自己约回来看看。你要它设的提醒和定时任务不受影响。
- 设安静时段（默认 23:00–08:00，按保存设置时浏览器的时区）：这段时间里它主动发的消息照样出现在聊天里，但不推送、页面也不提醒；安静时段结束后合成一条推送，告诉你它留了几条消息，还没读的聊天在打开的页面上再提醒一次。
- 设每天的推送上限（默认 20 条，可选“不限”）：只计算它主动发的消息的推送，合成的那一条算一条。超出后消息仍留在聊天里，只是不再推送。和它聊天、引导和设置、你要的提醒都不计入，所以刚开始频繁设置伙伴时不会用完。
- 查看“准备跟进的事”，逐条取消（立即生效）。已经开始发送的不能撤回。

“最近活动与结果”分别显示执行和通知／投递：等待、进行、完成、静默、跳过、失败或不确定不会混为“已送达”。可打开当前聊天、定时任务、渠道或用量页面核对；已归档、删除或无法确认的聊天会保留设置与修改并给出聊天列表入口，先恢复或核对，不自动跳到主聊天。刷新活动不丢掉未保存设置；取消跟进仍沿用原来的逐条取消入口。

这是有界的最近视图：读取全局最近 100 次定时运行、60 条渠道记录和现有最多 100 个定时任务，每个聊天只核对最近 100 代，最多显示 30 项。缺失来源和未报告的用量明确显示未知，不代表没有任务；不提供完整历史或整个伙伴的总费用。今日主动推送按伙伴保存的时区统计，用户定时任务共用的运行／tokens／费用额度按 UTC 展示，学习额度仍归该身份的辅助模型学习设置。

聊天与定时任务使用对话模型，空闲摘要也会额外调用这个伙伴的模型；后台学习另外调用辅助模型。关闭学习只暂停后台学习，关闭主动联系只暂停伙伴自己的跟进与推送，你设置的定时任务仍执行。安静时段和推送条数只控制通知，不能作为模型花费上限；已有的各类额度也不是整个伙伴的统一费用上限。

伙伴自己约的回来看看，它也可以自己取消；要取消你的承诺的到期提醒，按“做事方式”和取消定时任务一样先确认（“放手”和“稳妥”除外）。

这类消息不占用定时任务的每日执行和 token 预算，另有每个伙伴每天 50 次的安全上限；它们不出现在定时任务页面。伙伴连着微信时，推送的那几条也发到微信（安静时段留下的，在结束时逐条发出）；超出每日上限、没推送的不发微信。

在定时任务页面选择以伙伴身份为目标时，任务发送到该伙伴的主聊天，并始终进入主聊天当前的会话（换代后自动跟随）。已经开始的运行留在开始时的会话中完成，并一直使用任务开始时选定、用于预算核算的模型；运行结束后恢复伙伴自己的模型。定时任务页面中伙伴的“主线程”就是它的主聊天，不能改选或新建，页面只提供“打开主聊天”。

伙伴设置刚改过、主聊天空闲时，任务运行前会像手动“重新打开实例”一样重新打开主聊天以加载新设置，已打开的页面自动重连。主聊天正在运行、还有运行队列取回内容或扩展草稿、有侧聊或待发送的延迟消息、或配置正在保存时不会自动重开，按“线程忙碌”等待，在错过策略允许的时间内再试，超时记为跳过。

## 在微信里聊

（源码未发布）先在“设置 › 消息渠道”扫码连接微信并加入允许的微信用户，再在伙伴设置的“微信”里选一个微信用户点“连接”；也可以在消息渠道页的“项目或伙伴”里选伙伴后点“连接伙伴”。连接后这个微信聊天就和伙伴的主聊天连在一起：在微信里发的消息进入主聊天，伙伴的回复发回微信；网页里和它的对话结果也会发到微信（接收方式选“仅回复微信发起的消息”时除外）。聊天换到新的记录文件后，微信自动跟着走，不会分叉成另一段对话；正在换的那一刻发来的消息稍等片刻再处理。

一个微信聊天可以连多个伙伴，同一时间和其中一个聊。发送 `/help` 查看常用指令，`/help advanced` 查看高级操作：

| 指令 | 伙伴中的含义 |
|---|---|
| `/status`、`/status detail` | 当前伙伴、话题、配置／实际模型、做事方式和等待提示；detail 另列当前原生代的上下文与用量，不能当作整个伙伴或跨代累计，未报告时为未知 |
| `/stop` | 请求停止当前工作；不撤销已发生的操作 |
| `/model [搜索或 provider/id]`、`/model default` | 查询或持久保存整个伙伴后续回复的模型，default 恢复跟随默认，保留独立思考偏好 |
| `/thinking [等级]`、`/thinking default` | 查询支持的等级或持久保存独立思考偏好，default 清除偏好 |
| `/bot`（`/伙伴`、`/buddy`、`/切换`）`[序号或名字]` | 列出或选择伙伴，从它的主聊天开始；选中的伙伴加入当前微信连接 |
| `/topic`（`/话题`）`[序号或名字]`、`/topic main` | 列出或选择话题，main／主聊天返回主聊天；编号支持主聊天加最多 100 个话题，同名时要求明确选择 |
| `/new [标题]` | 新建并进入独立话题；保留原话题、主聊天和伙伴档案，排队中的后续输入跟随新话题 |
| `/name <标题>` | 只改当前话题标题；主聊天名称在伙伴设置里改 |
| `/confirm [卡片ID前缀]` | 确认媒体生成或查询已有结果；有多张匹配时要求更完整 ID，不代表工具授权 |
| `/compact` | 空闲时按伙伴的结构化摘要规则压缩；附加要求会被明确拒绝 |
| `/reload` | 空闲时重新加载当前聊天的技能、提示词和扩展资源 |
| `/resume`、`/reset` | 不执行原生线程操作，提示用 `/topic` 或 `/new` |

模型／思考设置和查询可以在回复进行时保存，当前 worker 不被改动；切换伙伴／话题、新建、命名、压缩、重载与媒体确认需要目标空闲。命令提交前重验允许用户、绑定与当前代；已提交或结果不确定的操作不自动重放。新话题请求有稳定身份，创建中断只恢复已预备的同一话题，不另建一个。

从微信发起的事需要你确认时（按“做事方式”），微信会收到这一步的内容和一个短编号，例如 A3：回复「同意 A3」只允许这一次，回复「拒绝 A3」不做；也可以照常在网页里处理，先处理的那边生效。编号只能由发起这件事的微信聊天使用一次，网页处理、30 分钟超时或这件事结束后就失效；“以后都允许”只能在网页里选。网页发起的事不发微信确认。

媒体 `/confirm` 与单步工具确认相互独立：`/confirm A3` 不会批准工具步骤，“同意 A3”也不确认媒体卡片。媒体卡片可从该窗口最近 100 代中查找有原生所有权证明的来源，最多取 50 张；无法核实、过旧或匹配不唯一时不猜测，失败或不确定的生成不自动再试。

连在这个聊天上的每个伙伴，它的定时任务结果和按主动推送规则放行的消息都会发过来；不是当前在聊的伙伴或话题时，前面带上【名字】或【话题名】。所在话题被归档、移到回收站或彻底删除后再发消息，这条不会发出，聊天回到主聊天并说明原因、提示你重发；伙伴停用或移到回收站后，发来的消息只会收到“不可用”的提示，可以用 `/切换` 换一个。断开一个伙伴后不再收到它的消息；断开的是当前在聊的伙伴时，换到另一个仍连着的伙伴，一个都不剩就解除这个聊天的绑定。聊天记录都保留。

## 当前限制

- 每个伙伴有一个固定主聊天及最多 100 个话题；归档话题计入数量上限。
- 空闲摘要和随后的换代在伙伴聊天的运行实例仍打开时进行；没有页面打开时运行实例在最后一次使用 15 分钟后关闭，提示缓存时间更长的模型可能等不到空闲摘要，届时由窗口快满时的自动压缩接替，换代顺延到下一次空闲整理。
- 整理摘要会额外调用这个伙伴的模型，长内容可能需要多段请求。最近一次摘要之后、伙伴自己没有记下的变化，要到下一次摘要时才同步到“我记着的事”。
- 换代时最近部分只带文字，工具输出不带入新会话；需要时伙伴可以翻找之前的聊天。
- 微信尚不提供完整设置表单或工具长期授权；可用 `/new` 开新话题，复杂表单和“以后都允许”仍在网页处理。
- 最近活动不是完整执行历史，执行完成不等于已送达；没有统一的整个伙伴费用上限。
- 伙伴主动发的消息只有到期跟进和它自己约的回来看看两类，只发文字；安静时段按保存设置时浏览器的时区计算，没保存过则按服务器时区。
- 工具权限是规则识别，不是沙箱；它不会分析被允许的程序内部行为。长期规则只覆盖可以理解的精确命令或单个文件，微信里只能同意或拒绝一次。
- 最多 50 个伙伴（与助手档案共用 50 个上限）。
