# 微信与消息渠道

安装或更新 OhMyBuddy 后，以服务端 `messageChannels` 能力和实际连接状态为准。它把微信 ClawBot 的私聊绑定到普通 OhMyBuddy 持久线程，网页和微信共用原生上下文、模型、助手身份与工具。

当前支持：

- **文字与图片输入**：微信发送文字或最多 6 张图片（经微信 CDN AES-128-ECB 解密并校验图像尺寸与格式），进入目标线程上下文。
- **确定性最终回复**：不推送流式过程碎屑，避免微信气泡刷屏；任务完成后按平台预算分段回传最终回复。
- **原生“正在输入…”状态栏心跳**：每次任务重新获取票据；上次请求完成后约 5 秒续期，不并发堆积心跳。任务结束会等待在途心跳并尝试取消；票据或网络失败时有界刷新，连续失败后暂停本次提示，消息处理仍继续。管理页显示提示异常，下次任务重新获取票据。
- **交互确认主动提醒**：当 Agent 请求网页交互确认（`confirm`、`select`、`input`、`editor`）时，立即向微信发送一条提示，提醒用户打开 OhMyBuddy 网页端处理。
- **常用斜杠指令（Slash Commands）**：支持 `/help`、`/status`、`/stop`、`/confirm [卡片ID或摘要]`、`/new [标题]`（或 `/reset`）、`/resume [序号|关键词|ID]`、`/name <新标题>`、`/model`、`/thinking`、`/compact`、`/reload`，直接返回管理简报或执行控制操作。
- **图片、媒体与文件成果回传**：本轮通过 `deliver_files` 发布的图片或文件，以及 `media_generate` 自动生成完成的图片/音频（合计最多 6 个、单文件 ≤ 16 MiB），自动加密上传至微信 CDN 并作为微信图片或文件消息发回；待确认的媒体生成卡片（如视频）在微信回复中附带卡片摘要，支持发送 `/confirm` 直接确认生成。
- **线程最终结果推送**：绑定默认接收该线程由网页、微信发起的最终结果及本轮交付文件；运行途中绑定也接收当前任务的最终结果。可改为“仅回复微信发起的消息”，已完成的历史不自动补发。
- **投递异常不再卡住聊天**：单条回复或定时通知发送失败、附件上传失败、发送回执未确认，都不会要求先到网页放行才能继续聊天。明确尚未发送的连接失败、限流拒绝和附件上传失败会有限重试；不确定是否已送达的内容保留记录，不自动重发。
- **定时任务主动推送**：新旧定时任务默认跟随目标线程的微信接收设置；每个任务可选择跟随线程、始终推送至已绑定微信或关闭通知，静默结束不发送。

语音转写、视频、普通微信群与微信内直接点击按钮确认暂未开放。包含未开放类型的微信消息不会截断交给 Agent，管理页会说明未进入线程。

## 安装与连接

1. 打开 **扩展 → 发现 → 在微信继续对话 → 安装与连接**，或直接打开 **扩展 → 消息渠道**。
2. 点击 **安装微信组件**。安装发生在运行 OhMyBuddy 的机器上；确认后才下载组件。默认安装 OhMyBuddy 不下载微信平台依赖、不启动微信连接，也不安装完整 OpenClaw 或 Hermes。
3. 点击 **扫码连接微信**，用手机微信扫描页面里的二维码。部分登录需要把手机显示的数字填入验证码框。二维码五分钟过期；离开页面不代表取消服务端登录，可返回继续查看或显式取消。
4. 登录成功后，扫码用户默认进入允许列表。允许用户可以在绑定线程内调用该线程已有的工具，因此只应加入你信任的用户。在账号卡片输入微信用户 ID 后回车添加，点标签上的 × 移除，“快速添加”列出扫码用户和最近联系过的用户；有未保存的修改时才出现保存栏，可撤销。已启用的连接不能保存空列表。凭据仅在服务端私有存储保存，不放进聊天记录。
5. 选择微信账号、已保存的允许用户、项目和已有线程，或选择 **新建微信对话线程**，点击 **绑定线程**。接收方式默认 **接收该线程的全部最终结果**，也可选择 **仅回复微信发起的消息**；已有绑定默认按全部结果接收，可用绑定行的 **接收设置** 修改。微信用户只能从已保存的允许列表中选择。也可以从线程菜单的 **连接微信…** 进入，自动选中该线程。
6. 在微信向已连接的 ClawBot 发送文字或图片消息。首次建立平台回复上下文前，网页／定时结果保留为待发送；在微信发来新消息后继续投递。绑定前的微信输入不会回放，绑定时尚未完成的任务会在完成后推送，已完成的历史不补发。先在网页配置可用模型；新建线程沿用现有创建规则与默认模型。

页面顶部汇总连接组件、账号连接、线程绑定和异常提醒；安装与绑定未完成时，组件卡片按步骤给出下一步操作，全部完成后显示“已就绪”。卸载组件和停用连接放在对应卡片的 `⋯` 菜单，执行前确认；解除绑定同样需要确认，绑定行可直接打开对应线程。

扫码连接的是 iLink bot 身份，不会把个人微信号的所有聊天自动接管。普通微信好友和群聊的能力取决于腾讯服务，当前 OhMyBuddy 仅开放私聊。长轮询不要求公网 webhook；部署机器需要访问 npm registry、微信 iLink 服务及微信 CDN，并使用 OhMyBuddy 既有网络/代理配置。

## 斜杠指令（Slash Commands）

下面的表适用于普通 Pi 线程。连接伙伴时使用 [伙伴指令表](BOT_MODE.md#在微信里聊)，模型、话题和确认的作用范围不同。

在已绑定的微信私聊中直接发送以下指令，由渠道服务直接处理。管理指令本身不作为聊天问题发送给模型；`/compact` 可调用模型生成摘要，`/confirm` 会按卡片参数调用媒体服务。

| 指令 | 作用 |
|---|---|
| `/help` | 查看微信端支持的全部斜杠指令说明 |
| `/status` | 查看当前绑定线程名称、会话 ID、项目路径、助手身份、运行状态（含等待确认提示与自动压缩开关）、当前模型与思考等级、上下文用量与占比、消息与压缩次数统计及累计 Token/费用 |
| `/stop` | 停止当前正在运行的任务；停止不会撤销已发生的外部操作 |
| `/confirm [卡片ID前缀\|摘要关键词]` | 确认生成当前分支最新的待确认媒体卡片（如视频），或查询最新卡片的完成结果并回传微信 |
| `/new [标题]` 或 `/reset [标题]` | 在当前项目下新建一条持久线程，并将当前微信聊天切换到新线程，原线程历史完整保留 |
| `/resume` 或 `/resume list` | 列出当前项目下最近活跃的前 10 条线程（带数字序号 `[1]..[10]`、标题、ID 前缀与消息数） |
| `/resume <序号\|标题关键词\|ID前缀>` | 按刚列出的序号、标题关键词或会话 ID 前缀切换当前微信聊天绑定的线程 |
| `/name <新标题>` | 重命名当前绑定的持久线程 |
| `/model` 或 `/model list` | 查看当前线程使用的模型、思考等级及可用模型列表 |
| `/model <名称或 provider/modelId>` | 切换当前空闲线程的模型 |
| `/thinking` 或 `/thinking <等级>` | 查看或切换当前线程的思考等级（如 `off`、`minimal`、`low`、`medium`、`high`） |
| `/compact [附加要求]` | 手动压缩当前线程上下文（支持附加自定义摘要保留要求），返回压缩前后 Token 对比 |
| `/reload` | 重新加载当前空闲线程的技能、提示词与扩展资源 |

`/resume` 的编号固定对应刚展示的候选 ID，在同一项目内 30 分钟有效。列表缺失、过期或选中线程已删除时，会要求刷新列表，不把编号挪给另一个线程。网页绑定与 `/resume` 都拒绝管理助手线程，包括保留旧版本原生身份标记的扩展助手和身份编写线程；拒绝不改变已有绑定，也不启动该管理线程。旧版本已经保存的误绑定在执行任务或发送待投回复前也会拒绝，原记录保留，需显式解除或改绑普通线程。`/model` 的裸模型 ID 若对应多个服务商，会要求指定完整 `provider/modelId`。

未知斜杠开头的文本仍按普通消息处理，不会透传为宿主内部导航命令。

连接伙伴的微信聊天（源码未发布）支持 `/help`、`/status`、`/stop`、`/confirm`、持久化的 `/model`／`/thinking`、`/bot`（`/伙伴`、`/buddy`、`/切换`）、`/topic`（`/话题`）、新建并进入话题的 `/new [标题]`、仅改当前话题标题的 `/name`；`/help advanced` 另列 `/status detail`、`/compact`、`/reload`。伙伴的 `/compact` 不接受附加要求，`/resume`／`/reset` 只提示话题替代操作。模型和思考等级对整个伙伴后续回复生效，`/model default` 保留思考偏好，`/thinking default` 清除偏好，不改变进行中的回复或已准入的定时任务；可以在正在回复时查询和保存，原生操作和话题切换需等空闲。普通 Pi 的模型指令仍只作用于当前线程。

微信发起的事等待伙伴工具授权时，回复「同意 A3」或「拒绝 A3」回答那一个仍在等待的步骤（只限发起的聊天、只用一次）；这些回复不送给模型。`/confirm [卡片ID]` 单独用于媒体生成或查询，不批准 A 编号工具授权；卡片可来自伙伴窗口有原生证明的较早代（最近 100 代、最多 50 张），歧义、失败或不确定结果不自动再执行。详见 [伙伴模式 · 在微信里聊](BOT_MODE.md#在微信里聊)。

## 线程、多模态与定时推送

- 一个账号下的一个微信聊天同时绑定一个当前线程，或连接伙伴（在“项目或伙伴”里选伙伴，点“连接伙伴”）。伙伴不按会话文件绑定：微信跟随伙伴聊天的当前记录文件，换代后自动跟随；一个聊天可连多个伙伴，同一时间和其中一个聊，其余伙伴的定时结果和主动消息带名字前缀发来。渠道页的绑定行显示伙伴名字和也连着的伙伴，`⋯` 菜单可逐个断开。每条绑定可单独设置 **启动提示**（默认开启）：当 OhMyBuddy 服务启动或重启并恢复该微信账号连接后，自动向该绑定聊天发送一条上线提示（纯渠道系统提示，不写入任何线程上下文，也不唤醒模型）；若该聊天尚未建立微信回复上下文或因长时间未互动被微信以 `ret=-2` 拒收，则直接静默跳过，不会积压为待核对或延后补发，同一聊天 60 秒内最多触发一次。更改或解除绑定前，先处理其排队输入、执行中任务、待发送回复或执行结果待核对的消息；单纯投递未确认的历史记录不阻止改绑。
- 同一微信聊天的普通消息和修改指令按顺序处理；`/new`、`/resume` 成功后，其后仍在排队的输入随该次切换进入新目标，不静默丢弃。无法证明原绑定有效时，只发送未执行说明，要求用户确认线程后重发。微信消息按线程空闲顺序处理。每个聊天最多保留 20 条尚未执行完成的输入消息（已完成任务的待发回复、投递异常记录与 `/stop`、`/status`、`/help` 控制指令不占普通输入队列额度）；最多同时派发 3 个线程任务。最近最多 4,500 个接收回执用于平台消息 ID 去重；原生当前分支也核对已登记的运行 ID。
- 微信执行期间，现有 worker 的独占操作保留到原生回合结算或进程实际退出。网页仍可读取实时记录，并可用线程的停止按钮中止当前微信任务；停止期间保留独占，直到实际结算。另一个会话写操作须等空闲。不会另开同文件 worker。
- 回复、交付文件和生成媒体均按原生轮次的开始与结算边界收集。延迟投递或恢复读取不会收集后来网页、微信或定时轮次的文件。全部结果模式在轮次完成时固定当前绑定，并登记持久投递意图；原微信发起者沿用原回执，只发送一次。绑定不会分享既有历史。
- 定时任务在完成时固定当时允许接收的绑定，并持久保存通知意图；只补处理尚未确认的本地投递入队，不重新执行任务，也不重放结果不确定的微信发送。之后替换绑定、撤销账号权限或关闭该任务的微信通知，会阻止对应尚未发送的内容。定时任务页显示待入队通知及无法建立的通知。
- 微信发图需要目标线程当前模型支持 `image` 输入；伙伴在已验证的新回合准入后先对齐已保存的模型（包括有效默认），再核对图片能力，查询、无效、重复或忙碌请求不会借此切模型；若模型不支持视觉输入，微信端会收到明确提示，可用 `/model` 切换模型后再发。
- 长回复按平台预算分段。超过 60,000 个字符时，微信回复明确提示到网页查看完整结果，原生记录保持完整。

线程被绑定时，网页删除或跨项目移动会要求先解除绑定。解绑、停用连接、卸载组件均不删除原生线程和历史。停用会取消尚未进入原生会话的排队消息；已运行的任务继续完成，回复保留为待发送。重新启用后可发送这些已完成回复，或先标记为已核对。

微信输入仍保存为原生 `pivane-channel-message`，不复制成另一条用户记录。回忆、摘要、记事本、交接、历史与学习通过同一只读适配器核验祖先链上的 `pivane-channel-turn` 开始记录、会话 ID、渠道／消息元数据、正文偏移和图片数，只有核实匹配才按用户发言读取；生成的投递说明剥离，原生条目、ID、分支、图片引用及渠道元数据保持。读取尊重最后的上下文编辑；任意 custom 消息、定时与子任务通知不能充当用户出处。

目标没有模型或不支持图片时，已确认未进入原生执行的输入会收到相应说明，之后的新消息仍可处理；修好模型后请显式重新发送该条请求，原拒绝不会自动重放。这与已提交、超时或结果不确定的执行不同，后者仍按下面的核对规则处理。

## 失败、重启与核对

**最近消息与投递**按最新在前显示最近最多 60 条记录，每页 5 条；刷新保留当前页，记录减少时自动回到有效页。“异常与提醒”包括发送失败、部分送达、投递未确认、等待回复上下文或交互确认的记录；“进行中”包括排队、运行和待发送。筛选、翻页和刷新只读，不会重发消息。

**普通投递故障不会阻塞后续聊天或定时通知。** 页面明确区分“投递未确认”和“任务执行结果需要核对”，展示已确认送达的文字段数、图片／文件数、经过筛选的微信返回码及附件说明。“标记已核对”是可选的记录整理，不是恢复后续投递的前置条件；旧版已经保存、且已开始发送的异常记录也适用，不会被改写成已送达或已人工核对。

发送前先保存投递状态，发送成功后保存平台回执。确定发生在消息发送之前的连接失败、明确的限流拒绝和附件上传失败，最多尝试 3 次，重试前分别等待 1 秒、3 秒，并重新检查账号权限、线程绑定和定时通知设置。已确认发出的文字不重发；附件逐个处理，一个附件上传失败或发送回执不确定时，保留其说明并继续其余附件，最后尽可能向微信补充附件提示。数量／大小超限、读取校验失败及尚未生成的媒体同样只影响相关附件。登录失效会明确提示重新扫码，不持续重复发送。

**微信长时间未互动后拒收（返回码 -2）不再需要核对。** 实测约一天没有在微信发消息后，微信会拒收这个聊天的定时通知和线程结果。系统把它识别为“回复上下文过期”，记录显示“等待微信消息”，不阻塞聊天、不要求“标记已核对”。在微信发任意一条消息后，等待中的结果用新上下文自动补发，每条最多尝试 3 次；超过一天仍未恢复的结果不再补发，保留在线程中。同一回复的文字已送达后某个附件被拒，只记为该附件未发送，不影响聊天。

超时、连接重置、无效响应和服务端网关错误可能发生在微信已接收消息之后，**不会自动重发，也不会重跑 Agent**。页面保留已确认数量；已完成回复不会因这类故障锁住后续消息。真正未收到的内容仍可在原线程查看。网页与定时结果缺少回复上下文时保留为待发送，在微信发来一条消息建立上下文后继续；绑定、权限或定时通知设置发生变化时仍重新核验。

有副作用的指令在执行前保存占位，实际提交前重新核对权限、绑定和取消状态；修改线程时保留受管 worker 互斥。已提交操作不能因后续撤权被撤销。服务重启时，执行中和发送中的记录保留为结果不确定，指令不自动重新执行。普通微信任务若尚未开始向微信发送，系统会自动读取原线程当前分支的原生完成记录；有明确完成证据时恢复回复，不重新执行任务。暂时缺少完成证据时，间隔 30 秒最多核对 5 次；暂时无法读取待发送原生回复也会有限重试。

**只有任务执行本身不确定时，才暂停该线程／聊天后续普通输入，且最多 5 分钟。** 期间系统自动核对原生完成记录；超时后聊天自动继续，不需要到网页放行，受管 worker 的独占仍保证不会和真正仍在运行的任务重叠。没有开始时间的旧记录不再暂停聊天。已完成结果的投递以及 `/status`、`/help`、`/stop` 仍可继续。

伙伴主聊天在回合开始时会附带隐藏的记事本和话题索引。早期版本把它们误判为外来输入，模型已回复但微信回复无法确认归属，记录停在“运行中”，服务重启后变成待核对并暂停聊天。现在这两类隐藏上下文按本回合内容处理；已经按旧逻辑记为失败的回合，若同一结算紧随的线程完成记录指向该回合的正常回复，会只读恢复并发送，不重跑任务。回合结束却暂时无法证明回复时，记录转为自动核对，不再长期停留在“运行中”。没有原生完成证据，或有副作用的指令结果不确定时，仍需查看实际线程／卡片后“标记已核对”；这不会重跑任务或补发回复。也可显式使用“核对并发送原生回复”再次尝试只读核对。Agent 请求网页交互确认、登录凭据失效和实际权限变化仍需相应操作。

连接出现网络错误时，长轮询有退避重连；这与消息执行和回复重放是不同操作。凭据过期时重新扫码。安装失败先刷新状态；校验失败不会加载不完整的组件。

组件安装失败会显示失败阶段（读取现有组件、下载组件、校验下载包、编译组件、加载与二维码自检、保存安装结果）和可安全展示的系统错误码，不展示响应正文、代理凭据或本机路径。先点击 **刷新状态** 核对实际结果，不自动重复提交。

Windows 上，原版 1.10.1 及更早版本的安装器可能因生成的文件 URL 缺少盘符，在加载自检时报 `ERR_INVALID_FILE_URL_PATH`，网页只显示“操作失败或结果待核对”。当前源码已改为从本机绝对路径生成 URL；需要包含该修复的版本或经核验的安装器补丁，重装同一原版不能修复。已通过加载自检的现有组件可以继续使用。

## 组件、数据与维护

OhMyBuddy 锁定腾讯 `@tencent-weixin/openclaw-weixin` 2.4.10 和 `qrcode-terminal` 0.12.0 的官方 npm 归档与 SHA256，下载后仅编译审查过的 API、无损消息 ID 解析、格式/加密辅助、CDN 上传下载与二维码模块。账户配置、网络传输和日志由 OhMyBuddy 适配，不执行上游插件入口、npm 安装脚本或安装 OpenClaw peer dependency。更新兼容清单随 OhMyBuddy 源码审查；当前不自动追踪上游 latest。两份归档约 220 KiB，具体安装大小以实际产物为准。上游字节、许可与适配说明保留在私有组件回执。

数据位于当前 Pi 身份目录的 `ohmybuddy-channels/`：

- `component.json`：可卸载的连接组件、完整性回执（v2）、上游原件与许可证。
- `state.json`：账号凭据、允许用户、微信上下文令牌、绑定、接收游标、尚未入会话的消息意图及投递元数据。旧版保存的 `typingTicket` 兼容保留但不再复用，新票据只在本次运行内存中使用。消息进入原生线程后移除意图正文与图片引用，不保存第二份聊天历史。
- `owner.sqlite`：服务所有权协调。同一身份只允许一个渠道服务持有账号；进程中断后的所有权在数据库事务内核对。

这些文件使用私有权限或 Windows DACL，位于应用版本目录之外；随身份目录一并备份。Git 与发行源码发现排除该目录。卸载只移除连接组件，保留账号与线程关联数据；当前没有删除账号/凭据的网页入口。组件未安装时不会启动账号连接。

登录、配置写入、执行和发送计入维护忙碌；常驻长轮询可在正常停机时中止。更新不得中断承载当前维护任务的服务。Linux 隔离测试或模拟微信接口不代表真实微信扫码与三平台实机验收。
