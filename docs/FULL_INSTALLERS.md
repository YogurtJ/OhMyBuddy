# 自带运行环境的完整安装包

完整平台包与源码归档不同：它包含专用 Node、匹配的 Pi、锁定应用依赖和搜索工具，Windows 还包含 Portable Git/Bash。首次安装只校验和复制已经准备好的文件，不运行 npm，不要求用户访问 GitHub 或 npm。模型服务仍需要自己的账户/API Key及可访问的服务。

维护者应在下载页只提供已通过对应平台原生验证的包，并标明预览、系统代码签名/公证和最低系统范围。源码支持构建某个目标，不代表该架构已实际验收。正式版的源码安装验证范围见[平台验证](RELEASE_INSTALL_VALIDATION.md)，完整包以其独立回执为准。

## Windows

当前构建目标为 Windows x64。下载 `.exe` 安装程序后双击；安装器会检查并复制运行环境，注册当前用户的低权限登录任务，然后打开浏览器。无需预先安装 Node、Pi、Git，也不要求管理员权限。安装过程需要临时解压和复制，建议预留至少 2 GB 空间。

默认位置为 `%LOCALAPPDATA%\Programs\OhMyBuddy`（旧安装继续识别原 desktop 位置）。后台任务由当前用户运行，私有隐藏宿主记录服务日志；关闭浏览器不会停止后台服务。任务在用户登录时启动，电脑睡眠、关机或用户退出会使其不可用。

预览安装程序若尚未作系统代码签名，Windows 可能显示发布者/SmartScreen 提示；只在核对下载来源后确认，不关闭系统保护。Windows ARM64 和其他系统版本不能沿用 x64 的验收结论。

## Linux

后续完整包发布以 **glibc Linux x64** 为维护目标；暂停为新版本制作和验收 Linux ARM64 完整包。历史 ARM64 包与对应验收仍可查阅，但不代表后续更新承诺；源码中保留既有架构适配。不适用于 Alpine/musl。随包原生组件需要 glibc 2.34 及以上、支持 GLIBCXX 3.4.29 的 libstdc++，常见基线为 Ubuntu 22.04+ / Debian 12+；既有原生验收包括 Ubuntu 24.04 x64 和历史 Debian 13 ARM64，ABI 基线不代表所有发行版均已实测。使用普通用户和具备用户级 systemd 的系统，不使用 `sudo ./Install.sh`。

解压匹配架构的 `.tar.gz` 后进入目录运行：

```sh
./Install.sh
```

默认位置为 `~/.local/lib/ohmybuddy`（旧 desktop 安装原位识别），服务注册到当前用户的 systemd。桌面环境会打开浏览器；无桌面的服务器输出本机地址。默认仅监听 `127.0.0.1`，远程使用可先建立 SSH 隧道，再按[网络与访问](ACCESS_CONTROL.md)配置自己的访问方式，不能为了简化安装而默认暴露未经配置的公网服务。

用户服务默认在登录时启动。服务器需要注销后继续运行或开机即启动时，由管理员按[后台常驻指南](BACKGROUND_SERVICE.md)为这个用户配置 linger；不要停止其他用户的服务或改用另一份 Pi 身份。

## macOS

下载匹配芯片的 `.dmg`，将 OhMyBuddy 拖入“应用程序”后打开。应用是首次安装入口，可写发布版本和数据保存在 Application Support。具体路径、权限提示与公证范围见[macOS 指南](MACOS.md)。

## 配置、更新与已有数据

首次打开后可直接开始会话，或打开自己的项目文件夹；缺少模型时按提示进入服务商设置。安装器使用 Pi 原生身份目录规则；已有身份不复制认证文件，也不要求重新创建账户。新安装的实例配置、媒体、后续发布版本与工作文件使用独立外部位置；已有路径不自动搬迁。具体平台位置、重装保留和卸载边界见[存储布局](STORAGE_LAYOUT.md)。

完整包在“设置 → 版本与更新”中通过签名渠道更新，由独立启动器完成准备、验证、正常停机、备份与切换。客户端不安装 npm 依赖。保存草稿、完成任务并停止共享身份的外部写入者后确认；网络结果不确定时查看同一维护任务，不重复提交。见[更新与恢复](UPDATES.md)。

OhMyBuddy 兼容既有 Pivane 位置与格式，但不自动覆盖未知源码安装。已有实例先核对目录、身份、端口和后台服务；检测到未知目录或冲突时保留现场。旧 Pivane 更新器不能直接读取新品牌包，须按[命名与迁移](development/NAMING.md)使用独立渠道和显式过渡包，不能只把旧 URL 改到新包。
