# 定时任务与主线程

本机或自托管实例须确认后端报告 `scheduledTasks:true`、目标 worker 加载 `cron-v3`（旧能力仅能读取／结束已支持的运行）；只刷新旧版网页不会更新后端。任务页初次读取时显示加载状态；读取失败可重试。普通 HTTP 局域网地址不提供浏览器 `crypto.randomUUID` 时，创建任务仍通过 `crypto.getRandomValues` 生成随机任务 ID。

在工作台导航进入“定时任务”（手机位于“更多功能”），可以创建、编辑、复制、暂停和删除任务，也可以手动运行一次。聊天输入框的加号菜单提供“创建定时任务”，打开表单并自动填入当前持久会话；无需输入草稿，临时会话或断线时不可用。线程操作菜单不再提供此项。身份概览的“主线程与定时任务”打开该身份的任务列表。

## 查看任务与历史

页面默认显示“当前任务”，按正在进行、重复任务、单次安排和已暂停分组；同组优先显示较早的下次执行时间。重复计划使用循环图标，单次安排使用日期图标，两者均显示文字类型。桌面首次进入时优先展开正在进行或即将执行的当前任务；手机先显示列表，点击任务再进入详情。

已结束且没有未完成运行的单次任务自动进入“历史任务”，包括完成、失败、停止和已错过的安排。记录和原线程保留；历史失败在列表中使用低强调样式，进入详情仍可查看具体失败原因。历史单次任务提供“重新安排”，使用新的任务 ID 打开草稿并要求选择新时间；打开草稿不会自动执行。重复任务仍保留在当前列表，暂停的计划单独分组。

搜索同时覆盖当前和历史任务，可按名称、任务内容或工作目录查找。“计划中”统计仍启用的有效计划；“待核对”只统计尚未解决的不确定执行，旧失败不长期计入该数字。正在等待、提交、运行或需要核对的任务始终留在当前列表顶部；即使后面新增了跳过记录，也不会掩盖未完成的运行。详情顶部直接提供停止或核对入口。

## 创建任务

1. 选择指定线程，或一个助手身份的主线程。工作目录可直接输入，也可点击“选择目录”，搜索现有项目或逐级浏览服务器允许的目录；目录选择不创建会话或更改项目权限。目录和线程选择窗口统一在屏幕中央显示，并在窗口内部滚动。线程支持搜索名称、身份、首条消息和 ID，较长列表可继续加载；方向键选择结果，Enter 确认，Esc 关闭并返回原控件。更换目录后会清除不属于新目录的线程选择，读取失败可重试。普通无身份线程也可作为目标；管理线程不接受定时任务，身份归属由原生线程决定。
2. 选择每天、工作日、每周（选择星期）、自定义五段 cron 或单次日期，并核对未来五次时间。周期时间使用明确的 IANA 时区，例如 `Asia/Shanghai`；单次日期按当前设备时区输入，预览按所填目标时区显示。
3. 可指定“生效时间”，自动执行只会安排在该时刻及以后；留空立即生效。此字段按当前设备时区输入，预览按任务时区显示。编辑其他字段而未改时间时，保留原单次时间和生效时间的完整精度。手动“运行一次”仍可提前执行，提前运行完成不取消原定的未来触发。
4. 填写任务说明。文字模式只允许生成文字和使用静默结束工具；工作模式使用原线程的工具与权限。任务会使用目标线程的现有上下文。首版不提供自动媒体生成或跨线程委派。
5. 常用的目标、时间与任务内容优先显示；“执行设置”与“模型、调度与可选限额”按需展开。可跟随目标线程模型，或固定供应商、模型和该模型支持的思考等级；设置错过策略、用户活动条件和预算。
6. 微信通知默认 **跟随线程的微信接收设置**：目标线程绑定为接收全部最终结果时，该任务完成后自动推送。已有任务也按此规则执行，无需逐个开启；旧配置中的默认 `notifyWeixin:false` 视为跟随，原先主动开启的任务保持推送。可单独选择 **推送至已绑定微信** 或 **不发送微信通知**；静默结束始终不发送。
7. 新任务默认停用。勾选“保存后启用”或保存后点击“启用”，服务才会自动执行。“运行一次”会实际调用模型，也受预算和互斥限制。

暂停阻止后续触发并取消尚未提交的排队运行，不等于中止正在执行的工作；正在运行的一次需单独点击“停止”。删除任务保留已有线程、回复与执行记录，不撤销工作产生的副作用。

## 主线程

每个 profile 最多一个主线程，按需创建，也可以指定已有的同身份普通线程。任务编辑器选择“身份的主线程”后，在明确的工作目录中指定或创建。创建的是普通原生持久会话，在工作台对应的真实项目下显示。

主线程引用不改变线程历史或身份。更换主线程后，尚未开始的任务使用新目标；已经提交的运行保留原目标。删除主线程会标记引用失效并暂停相关任务，不自动重建。重新指定目标后显式启用任务。禁用或缺失的身份不能启动新定时运行；运行实例尚未加载最新身份配置时需空闲后重开。

创建响应不确定时先刷新核对；保留同一请求 ID，不重复创建。若页面提示创建待核对，在线程列表找到已保存的会话再指定为主线程。

## 时间与恢复

五段表达式为“分钟 小时 日期 月份 星期”，支持数字、列表、范围和步长，星期日可写 0 或 7；日期与星期同时限定时按通常 cron 的 OR 语义匹配。不支持秒字段、自然语言、`@` 别名或 `L/W/#` 扩展。预览最多向前检查八年。夏令时不存在的时刻跳过，重复的本地时刻只选择首次出现。

- **直接跳过**：服务离线时错过的触发不补发。正常运行时容许一分钟调度／线程空闲窗口，超过后记为跳过，避免迟到问候。
- **补最近一次**：宽限期 1–1440 分钟内只选择最近的一次触发。不会把停机期间所有任务集中补跑。
- **线程忙碌**：等待，不插入用户的当前任务。每任务最多一条未结束运行；后续重叠触发记录为跳过。全实例默认同时执行两项，可在全局设置调整为 1–10 项；不确定执行保留占用，先核对再释放。
- **不确定结果**：提交前持久占位，原生线程按 run ID 去重。重启时提交中／运行中标为不确定，不自动重放；已打开线程中存在完成回执时可核对恢复。否则先查看线程，再选择“核对并结束”，恢复模型／工具设置后结束这一项，不重新执行。

普通受管线程启动时，定时扩展保持已有原生工具选择，包括已选中的子任务回复工具；不会默认启用静默结束工具或重新启用明确禁用的工具。若最后一次模型请求来自定时任务，原生记录仍可能包含静默结束工具；恢复时先完成其他工具注册，再在普通回合开始前移除它，避免丢掉尚待注册的原生选择。

定时调度由服务端负责，浏览器可以关闭。worker 可按原有条件在无订阅且空闲 15 分钟后退出，到点由 Supervisor 启动同一线程的唯一受管 worker。未来触发不阻止维护；正在派发、保存、执行或恢复的工作参与生命周期与停机判断。

## 执行设置、反馈与可选限额

新任务使用第 3 版执行策略：新建表单默认“执行工作”，工作和文字模式均默认不限制模型调用次数，最长 6 小时；文字模式仍不使用工作工具。单次和每日累计 Token、每日次数与估算费用默认不设硬上限，仍记录实际用量。任务使用目标线程的上下文、工具和权限；本版不自动另建独立任务会话或改写历史。

“执行设置”可调整模型调用次数（留空不限，或 1–10000）、最长执行时长（10 秒–24 小时）、停滞时长（30 秒–24 小时，可留空关闭）和相同工具连续失败次数（2–100，可留空关闭）。默认停滞时长 15 分钟，仅在没有模型新输出且没有工具执行时计时；运行中的工具仍受整次时长限制。同一顶层工具的输入和错误连续重复 5 次时停止，成功或不同错误重置计数。正常的重复查询不会仅因参数相同而停止。

“模型、调度与可选限额”中，单次 Token、单次估算美元、每日次数／Token／美元均可留空。累计 Token 包含每次请求的输入、输出、缓存读取与缓存写入；20 万上下文执行 20 轮可能累计约 400 万 Token，不等于模型上下文窗口或新生成文字的长度。费用按实际用量中的分类价格累计，未知费用保留未知；零用量的中止占位不会把此前已知费用改为未知。

“全局设置”提供 1–10 项并发（默认 2）及可选共享每日限额，按 UTC 日统计。达到并发时排队，同一任务始终不重叠。任务限额与实例限额同时生效；启用每日限额时，启动在同一个调度独占区预留本次可用额度。未设置单次限额时，最多预留剩余每日额度，并把有效上限传给 worker。已有不确定费用会阻止启用了费用上限的后续运行，不能当作免费。

旧任务保存的显式限制与已保存的实例限额原位保留，升级不根据数值猜测是否为默认值。同一策略下的部分编辑会保留省略的费用和保护参数，显式 null 才清除可选限制，避免旧客户端无意取消新限额。编辑器会说明旧策略，并提供“使用推荐设置”：填入推荐时长／停滞保护，清空调用次数以及此任务的单次和每日配额；点击保存后才生效。实例共享限额需在全局设置中单独调整。正在执行的运行保留准入时的策略，失败或已结束的运行不会因修改设置而自动重放。

停止或失败时，运行记录显示具体原因、可用的错误详情、处理建议，以及调用／Token／费用的已用量和有效上限。已提交执行的失败会在原线程追加 `pivane-cron-result` 结果卡，不触发新模型回合；启动前失败保存在调度记录中。已启用的浏览器通知显示原因，已配置的微信通知同样带原因和建议。微信未绑定、通知关闭或发送不确定时，不假称用户已收到；调度执行状态和投递状态分别保留。不确定执行必须先核对线程与外部操作，再决定是否结束或手动运行。

“今天此时之后有用户消息则跳过”只检查目标线程当前原生分支的用户消息，按任务时区判断日期；不把 Agent 消息和定时任务当作用户回复。命中时不调用模型。否则模型也可以使用 `cron_silent` 明确静默结束，运行记录保留但不发送完成提醒。

可选限额是费用控制与估算，**不是供应商扣款的硬上限**：在模型调用边界检查，已经发出的请求可能超额；停止请求也要等待实际结束。第三方中转差价、缓存预热、压缩或工具嵌套请求／额外收费不保证全部覆盖。工作模式具备原线程系统权限，预算字段不把任意 Shell、扩展或外部服务变成费用沙箱。文字模式适合问候与简报。

最多 100 个任务记录（包括已删除记录）和 10000 次运行记录，达到容量后拒绝新增，不自动删除历史。页面每任务显示最近 100 次。暂停／删除任务不会删除统计或释放已消耗预算。

## 数据与接口

私有调度配置、主线程引用、占位和用量元数据保存在 `<agentDir>/ohmybuddy-cron/scheduler.sqlite`。使用 SQLite FULL 事务和私密权限；同一原生身份只允许一个调度器持有者。持有者由同目录 `scheduler.sqlite.owner.sqlite` 上的系统排他锁确定，进程退出（包括崩溃、强制结束或机器重启）后自动释放；残留的旧 `owner` 记录和被复用的进程编号不会阻止启动，无需手工清理数据库。锁文件可以保留，运行期间不要删除或替换它。升级时须先停止旧版本，再启动新版本，不能让采用旧占用判断的版本与新版本共用同一身份并行运行。

备份完整身份目录时包含此目录。任务说明、回复和原生执行回执保存在唯一原生会话中；数据库不复制回复正文。

接口沿用工作台认证、Origin 校验和 `no-store`；内部 worker 凭据不能作为管理授权。

| 接口 | 参数与行为 |
|---|---|
| `GET /api/pi/cron` | 任务、主线程、实例预算、今日占用、最后运行 `lastRun`、尚未结束的运行 `activeRun`（无则 null）与容量；有调度故障时包含 `schedulerError` |
| `PUT /api/pi/cron/jobs` | 稳定 UUID `id`；更新带 `revision`；`name,prompt,enabled,mode,weixinNotification,target,schedule,model,misfire,condition,execution,budget` |
| `PATCH /api/pi/cron/jobs/:id/policy` | `{revision,execution?,budget?}` 仅调整执行与额度；保留目标、提示词、计划时间、启停和历史，允许已过期单次任务，拒绝有未结束运行的任务 |
| `POST /api/pi/cron/jobs/:id/actions` | `revision,action`；`pause/resume/delete/run/stop/acknowledge`；run 必须带稳定 UUID `requestId`，stop/acknowledge 带 `runId` |
| `GET /api/pi/cron/jobs/:id/runs` | 最近 100 项，包含原生结果 entry ID、实际目标、模型和用量，不复制回复 |
| `POST /api/pi/cron/preview` | `{schedule}`，返回最多五个毫秒时间戳 |
| `GET/PUT /api/pi/cron/limits` | GET 返回 `{limits,settings,revision}`；PUT 带相同 revision 和 `limits`，可带 `settings:{maxConcurrent}`，校验后同一事务保存，省略 settings 保持原值 |
| `PUT /api/pi/cron/homes/:profileId` | `{revision,cwd,sessionId}` 指定线程；或 `{revision,cwd,create:true,requestId,language?}` 创建并指定 |
| `GET /api/pi/cron/models?cwd` | 真实可用模型、思考等级及默认值 |

`weixinNotification:'inherit'|'on'|'off'` 分别为跟随线程（默认）、推送至已绑定微信、关闭通知。兼容旧客户端显式提交的 `notifyWeixin:true|false`，分别转换为 on/off；已存旧任务无新字段时，true 保持 on，false／缺失按 inherit。通知只面向任务完成时有效的绑定，不补发绑定前已完成的历史。

`target` 为 `{kind:'thread',cwd,sessionId}` 或 `{kind:'profile',profileId}`。伙伴的 profile 目标还可带 `windowId`（UUID，必须是该伙伴的窗口）；省略时进入主聊天，提供时每次运行经 `bots.resolve(profileId,windowId)` 进入该窗口当前一代，不保存固定会话 ID。伙伴在聊天里创建的任务默认启用，话题窗口带 `windowId`，仍可在任务页面按原有修订编辑；同一 profile 的编辑请求省略 `windowId` 时保留已有窗口，避免旧表单无意转到主聊天，显式提供另一窗口 UUID 才更换窗口。`schedule` 为 `{kind:'cron',expression,timeZone}` 或 `{kind:'once',at,timeZone}`。`startsAt:null|毫秒时间戳` 指定自动执行的最早生效时刻，允许未来八年内；保存、启用和预览均应用该下限。`model:null` 跟随线程，否则为 `{provider,modelId,thinkingLevel}`。`misfire:{policy:'skip'|'latest',graceMinutes}`；`condition:null` 或 `{kind:'no-user-since',time:'HH:mm'}`；`policyVersion:3` 标明可选调用上限的新执行策略。新任务缺省为 3；版本 1、2 仍可读取和编辑，省略版本时沿用原策略。明确设置 3 和完整参数才切换。`execution:{maxCalls,maxTokens,maxCost,maxDurationSeconds,maxIdleSeconds,maxRepeatedErrors}` 中 maxCalls/maxTokens/maxCost/maxIdleSeconds/maxRepeatedErrors 接受 null；`budget/limits:{maxRunsPerDay,maxTokensPerDay,maxCostPerDay}` 均接受 null，表示只统计、不设硬上限。每日次数最大 100000，累计 Token 最大 1000000000000，估算美元上限最大 10000。`GET /cron` 的 `settings.maxConcurrent` 和 `capabilities.defaults` 提供当前并发与文字／工作默认策略，客户端不需要猜测后端默认值。运行的 `execution` 保存准入时的有效限额；`feedback:{code,title,suggestion,detail?,usage?,limits?}` 保存失败诊断，`usage` 另含 input/output/cacheRead/cacheWrite 分类。原因标识包括 token-limit/call-limit/cost-limit/cost-unknown/time-limit/idle-limit/repeated-errors/daily-runs/daily-tokens/daily-cost/model-error/user-stopped/worker-policy/submission-uncertain/reconciliation-error；旧 run-limit 保留解释。

运行状态为 `waiting/dispatching/running/completed/silent/skipped/failed/error/stopped/cancelled/uncertain`。修订冲突返回 409 并保留本地草稿。响应不确定先查询原 ID；不要生成新 ID 重复运行。运行未结束时拒绝编辑／删除任务，暂停仍可用。

## 从其他调度器迁移

先以停用状态建立任务，核对时区、模型、工作目录、提示词与投递目标，再受控试跑。选定切换时间，确认旧任务没有正在运行或待交付结果，暂停旧调度器中的对应任务并核实后，再启用新任务。从切换后的下一次计划开始，不补发历史问候。保留旧配置用于回退，回退时先停用新任务再恢复旧任务。

旧服务的消息平台、工具名称、图片路径和技能不是可直接移植的执行能力，需逐项适配。首版文字任务不执行旧提示词中的自动生图。
